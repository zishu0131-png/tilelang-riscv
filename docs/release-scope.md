# 发布范围与限制

## 这份快照是什么

本版是 2026-10-29 整理的研究源码展示副本，不是研究工作区的完整镜像。前端取冻结基线 `20261026-183`，不含其后未合入候选；RVV 取独立消费器的指定核心文件。逐件文件身份见根目录 `release-manifest.json`。

## 有意不包含

- 内部交接、讨论、授权记录与历史快照目录。
- 外部仓库语料、来源与许可未逐件确认的上游样例。
- 本机连接、账户认证、绝对工作区配置。
- 缓存、ELF、汇编产物及其他构建输出。
- 尚未合入的线程映射修订。不能把后续候选的 CUDA 编译或 GPU 数值结果记在此版本名下。

## 发布副本的改动

前端 29 件冻结文件保持原字节；额外演示脚本另建，不改冻结实现。旧诊断测试额外依赖 `composition.py`，此辅助模块按原字节单列加入 manifest，不冒充 183 冻结成员。只复验其 `Node/describe` CPU 路径；`load_graph` 会执行目录中的 Python 模块，仅可用于可信本地生成物，本次没有运行或验证该路径。

RVV 的 `backend.py` 和 `examples.py` 原版会默认设置 `KMP_DUPLICATE_LIB_OK=TRUE`。发布副本去掉这项自动绕过，保留算法代码。发生 OpenMP 运行时冲突时应修复环境，而不是默认忽略冲突。这个包装改动意味着历史环境运行结果不能自动算作发布副本重新验证通过。

## 验证口径

历史研究环境有 14 个 RVV kernel × 3 个 VLEN 的功能验证记录；这表示 42 次配置运行，不是 42 个独立算子。它们也不是本次发布副本的新测试结果。本仓库保留对应示例与运行入口供复现，但不搬运含本地路径的原始历史输出。

曾串联的选定上游 tile 级样例不随首版发布，不能据此宣称任意原始 Numba 程序已经自动迁移到 RVV。

- 前端 CPU 源码转换成功不代表 TileLang 设备编译成功。
- IR 结构检查不等于浮点数值验证。
- 数值相同不单独证明没有重复写或竞争。
- 检查到 RVV 汇编指令不单独证明结果正确。
- QEMU 单 hart 功能验证不等于多核正确性、真实硬件部署或性能。

## 已知限制

- 支持子集由具体入口、模式、数据类型、布局和边界条件共同限定；没有全量 Numba CUDA 兼容性承诺。
- RVV 输入使用 TileLang 绑定的 `tvm.tirx`，不是任意版本 TVM 的通用 IR。
- RVV 中 block 顺序执行，shared/fragment 存储映射为单 hart 局部数组；这不是 GPU 硬件模型仿真。
- `threadIdx` 依赖寻址、跨 hart 同步以及未支持节点应拒绝。
- Clang/QEMU 的默认路径适配原 Windows 开发环境；其他系统须设置工具路径。跨平台复现尚需实测。
- 不包含真实 VCIX 契约、实现、硬件验证或性能结论。
